# ImaginAI - システム仕様

## 1. システム概要

ImaginAIは、AI画像・動画・音楽・音声生成APIを専用GUIで操作するデスクトップアプリケーションである。Electronで構築され、複数のAPIプロバイダを並列にサポートする:

- **Google AI Studio** (内部識別子: `gemini`): Gemini Nano Banana 系 (画像) / Gemini Omni Flash (動画) / Lyria (音楽) / Gemini TTS (音声)。`@google/genai` SDK 経由で呼び出す。
- **OpenAI** (内部識別子: `openai`): GPT Image 2.6 (Flare / Sunburst) (画像)。`openai` SDK 経由で呼び出す。

両プロバイダはデータスキーマ・UI 構造ともに完全に対称な形で扱われる。コード内識別子は `gemini` / `openai` で統一し、ユーザー向け表示文字列のみ「Google AI Studio」「OpenAI」を使う二層構造で運用する。

## 2. アーキテクチャ

### 2.1 プロセスモデル

- **Mainプロセス**: IPC通信、ファイルI/O、API呼び出し、設定管理、APIキー暗号化、ウィンドウ管理を担当する。
- **Preloadプロセス**: `contextBridge`を通じてMainプロセスとRendererプロセスを安全に橋渡しする。
- **Rendererプロセス**: React + MUI によるUIを担当する。

## 3. 機能仕様

### 3.1 画像生成

- ユーザーはモデルを選択し、パラメータ（アスペクト比、解像度、生成枚数）を設定し、プロンプトを入力し、任意で参照画像を添付する。
- パラメータはモデルの対応状況に基づいて検証される（例: 21:9は対応モデルのみ、4Kは対応モデルのみ）。モデルが画像入力非対応の場合は参照画像UIが非表示、ネガティブプロンプト非対応の場合はネガティブプロンプト欄が非表示、生成枚数が1枚のみのモデルでは枚数スライダーが非表示となる。
- 出力フォーマットは Gemini では PNG（API の既定値。`response_format.mime_type` は指定しない）、OpenAI では PNG / JPEG / WebP から選択できる（その他のパラメータは 3.1.1）。セーフティフィルターは Gemini では API 側で制御されユーザー選択不可、OpenAI ではモデレーション（`moderation`: Auto / Low）を選択できる。
- 参照画像はファイル選択、ドラッグ＆ドロップ、または履歴エントリから追加できる。サムネイルとして表示され、個別に削除可能。
- 「生成」ボタンでAPIリクエストを送信する。生成中はボタンが無効化され、ローディングインジケータが表示される。
- 成功時は結果が自動的に履歴に保存される。失敗時のメッセージは2層構造で扱う:
  - **インフラ系エラー**（HTTP 4xx/5xx、gRPCステータス、ネットワーク等）: ユーザー向けに行動指針付きで言い換えたローカライズ文言を表示。
  - **コンテンツ系ソフト失敗**（HTTP 200だが生成物0件: Safetyブロック、Recitation、モデル拒否等）: 「{種別}が生成されませんでした。詳細を確認してください。」のみ事実として表示する（プロンプト変更を促す不確かなアドバイスは出さない）。
- 「詳細」リンクをクリックすると、APIから返された診断情報（Interactions API の `status`、モデルが返した拒否理由テキスト等）を生で確認できる。
- ネットワークエラー発生時はリトライボタンを表示し、ユーザーがリトライ可否を選択できる。
- 生成前に履歴保存先のディスク空き容量を確認し、100MB未満の場合は警告を表示する。
- 履歴件数が設定された上限（10,000件）を超えている場合、生成がブロックされる。

#### 3.1.1 OpenAI のパラメータ

GPT Image 2.6 で指定できるパラメータの扱い（OpenAI の API リファレンスと画像生成ガイドに準拠）:

| パラメータ | 扱い |
| --- | --- |
| `size` / `quality` / `output_format` / `n` | 選択値を送る |
| `background` | `openai.supportsBackground` のモデルのみ選択値を送る。透過は PNG / WebP のみ |
| `complexity` | Low / Medium / High（既定 High = API の省略時と同じ）。`openai.supportsComplexity` のモデルのみ送る |
| `moderation` | Auto（既定）/ Low |

- アニメーション GIF 出力（`output_format: "gif"`）と SVG 出力（`output_format: "svg"`）は扱わない。
- `markup`（編集時に重ねる書き込み画像）は未対応。
- `openai` SDK の編集用パラメータ型は `moderation` を宣言していないが、API リファレンスでは編集エンドポイントも受け付けるため、型を補って送る。

### 3.2 履歴管理

- 各生成結果はメタデータ（JSON）と生成ファイル（画像/動画/音楽）として保存される。
- 履歴はサムネイルグリッドでフレックスレイアウト表示され、更新日降順でソートされる。ページネーション（50件ずつ）によるインフィニティスクロール（遅延ロード）で表示される。
- 画像のサムネイルと幅・高さ: サムネイルは JPEG（長辺 300px）で、JPEG は透過を保持できない。透過を含みうる画像（WebP 全般と、IHDR の color type が 4 / 6 または tRNS チャンクを持つ PNG）は、同梱 ffmpeg で縮小したうえで市松模様（8px 角、白 255 とグレー 204）の上に重ねて JPEG にする（`extractImageThumbnail()`）。透過部分の下に記録された色はエンコーダ次第（黒・白など）で、透過情報を捨てるだけだと不定の色になるため。ffmpeg が使えない場合、透過 PNG は `nativeImage` で JPEG 化する（透過部分の色は保証されない）。Electron の `nativeImage` は PNG / JPEG のみを読め、WebP に対しては例外を出さず空の画像を返すため、WebP の幅・高さはファイルの RIFF ヘッダ（`VP8 ` / `VP8L` / `VP8X` の各形式）から読む（`readImageDimensions()`）。画像ビューアのウィンドウサイズも同じ関数で決める。サムネイルファイルが無いか 0 バイトの場合は、元画像をそのまま表示する。
- 左クリックでモードレスビューアウィンドウに画像を表示する（動画の場合は動画ビューアで再生、音楽の場合は音楽プレイヤーで再生）。複数枚生成の場合、すべてをそれぞれ別ウィンドウで開く。
- 右クリックでコンテキストメニューを表示: プロンプトに追加、名前をつけて保存（複数枚の場合は各画像のダイアログを順次表示）、パラメータ復元、削除。
- ヘッダーメニュー: すべて削除、すべて圧縮保存して削除（ZIPエクスポート、圧縮中はプログレスバーを表示）。
- 各エントリには生成所要時間（API呼び出し開始から完了まで）が記録され、履歴カードに表示される。
- 履歴パネルの高さは上辺のドラッグで調整可能。
- プロンプトテキストによる部分一致検索でフィルタリング可能。

### 3.3 動画生成

動画モデルは Gemini Omni Flash のみで、Interactions API（`interactions.create`）経由で生成する。

#### Gemini Omni Flash（キー `gemini-omni-1-flash` / API モデル `gemini-omni-1.2-flash`）

- 2026/11/5 GA の Gemini Omni 1.2 Flash を使う。
- パラメータは長さ（3〜15 秒の 1 秒刻み、既定 10 秒）、アスペクト比（16:9 / 9:16）、動画解像度（360p / 720p 既定 / 1080p / 4K）。1080p と 4K はアップスケールによる出力。
- 長さは `response_format.duration`（`"10s"` 形式の文字列）で送る。API 仕様上、プロンプト内で指定した長さよりこの値が優先される。最初と最後のフレームを指定する補間は API 側で 10 秒までに制限されており、超えると API が INVALID_ARGUMENT を返す（アプリ側では検証しない。モデルセレクタ下の注釈 `gemini.model.note.omniFlash` で案内する）。
- BGM・効果音はプロンプトで指示する。音声はモデルが自動生成する。
- ネガティブプロンプトは API 非対応（`supportsNegativePrompt` 未宣言のため UI 非表示）。
- 参照画像は最大 6 枚。画像に用途を示すフィールドは無く、開始フレーム・最初と最後のフレーム・被写体参照（キャラクター 2 人まで、1 人 3 枚まで）のどれとして使うかはモデルがプロンプトから判断する。参照画像エリアには「使い方はプロンプトで指示する」旨の案内（`prompt.videoReferenceHint`）を表示する。
- 動画固有の UI（長さ、動画解像度）が表示され、画像固有の UI（出力解像度）は非表示となる。シード値は UI に無い。
- リクエストは同期型で、呼び出しが完了まで数分ブロックすることがある。経過時間表示はサービス内のローカルタイマー（5秒間隔）で `GENERATION_PROGRESS` イベントを発火して実現する。
- レスポンスの動画は inline（Base64、`output_video.data`）が既定。大きい動画で URI（`output_video.uri`）が返された場合は `x-goog-api-key` ヘッダー認証でダウンロードする。
- 生成された動画は MP4 形式で履歴ディレクトリに保存される。サムネイルは ffmpeg により 1 秒目のフレームから抽出される。ffmpeg が利用不可の場合はサムネイルなし。
- レスポンスメタデータとして interaction ID（`HistoryEntry.gemini.interactionId`）とトークン使用量（`usageTokens`）を履歴エントリに記録する。
- 会話型動画編集（`previous_interaction_id`）・動画延長・参照動画（Files API）は未対応（テキスト/画像→動画のみ）。

### 3.4 音楽生成

- Lyria モデル（Lyria 3 Clip / Lyria 3.5）による音楽生成に対応する。いずれも Interactions API 経路。
- **Lyria 3 Clip**（キー `lyria-3-clip` / API モデル `lyria-3-clip-preview`）: 30秒の短いクリップを生成。$0.04/曲。
- **Lyria 3.5**（キー `lyria-3` / API モデル `lyria-3.5`）: 数分程度のフルレングス楽曲を生成。$0.08/曲。曲の長さ・構成はプロンプトで指定。2026/9/3 GA。`response_format` 省略で MP3 出力。レスポンスの `output_audio` から音声、テキストブロックから歌詞・楽曲構成を取得し、interaction ID とトークン使用量を履歴に記録する。
- Lyriaモデル選択時は画像・動画固有のUI（アスペクト比、解像度、生成枚数、長さ）がすべて非表示となる。
- プロンプトでジャンル、雰囲気、楽器、BPM、キー、歌詞（`[Verse]`, `[Chorus]`, `[Bridge]`セクションタグ）、タイムスタンプ指定が可能。歌詞に関する指示をプロンプトに含めることで、歌詞付き楽曲を生成できる。
- 参照画像を添付することで画像→音楽生成（Image-to-Music）が可能。公式上限どおり **10 枚**まで添付できる。

#### 参照画像の前処理（image / video / music 共通）

全ての生成経路で、APIに送る前に Electron `nativeImage` で以下の前処理を行う:

1. デコード
2. 長辺が **1920px** を超える場合のみ、縦横比を維持して縮小（`quality: 'best'`）
3. **JPEG (品質 85) に再エンコード**（PNG/WebP 入力も JPEG に統一）

枚数上限は各モデル定義の `maxReferenceImages` フィールドで宣言する（省略または 0 は画像入力非対応）。現状の値:

| モデル | maxReferenceImages |
| --- | --- |
| Nano Banana 2 Lite / 2.1 / Pro | 14 |
| Gemini Omni 1.2 Flash | 6 |
| Lyria 系 | 10 |
| Gemini TTS 系 | 未定義（画像入力非対応） |
| GPT Image 2.6 Flare / Sunburst | 16 |

Nano Banana の各モデルはいずれも合計 14 枚が公式上限で、内訳のみモデルごとに異なる（Nano Banana 2 Lite はオブジェクト14枚、Nano Banana 2.1 はオブジェクト10枚＋キャラクター4枚、Nano Banana Pro はオブジェクト6枚＋キャラクター5枚＋スタイル参照3枚）。アプリ側は合計上限のみを宣言し、内訳の振り分けはモデルに委ねる。

画像編集モードでは枚数 1 の単一スロットとして扱い、UI で新しい画像を添付すると直前の画像を上書きする。上限の算出は `resolveMaxReferenceImages()`（編集モードは常に1枚）に集約している。

- ネガティブプロンプトは非対応。
- 生成された音楽は履歴ディレクトリに保存される。保存形式（拡張子）はAPIが返した`mimeType`に基づいて決まる（通常はMP3、44.1kHz ステレオ、SynthIDウォーターマーク付き）。
- APIレスポンスにテキストパート（歌詞、楽曲説明、BPM等のメタデータ）が含まれる場合、`audioTexts`フィールドにparts順序のまま配列として保存される。テキストパートの内容や数はAPIの挙動に依存し、構造的なラベル区分はない。
- 履歴パネルではサムネイルの代わりに音楽アイコンで表示される。
- クリックで音楽プレイヤーウィンドウ（モードレス）が開き、HTML5 `<audio>` 要素による再生コントロール付きで自動再生される。テキストパートがある場合はプレイヤーウィンドウ内にパートごとに区切り線付きで表示される。
- API は Lyria 3 Clip / Lyria 3.5 のいずれも `/v1beta/interactions` を使用し、`output_audio` / `output_text` から音声と歌詞を取得する。
- Single-turn only（マルチターン非対応）。

### 3.4.1 音声合成（TTS）

- Gemini TTS モデルによるテキスト読み上げ生成に対応する。いずれも Interactions API 経路。
- **Gemini 3.8 Flash-Lite TTS**（キー `gemini-3-flash-lite-tts` / API モデル `gemini-3.8-flash-lite-tts`）: 高スループット・低コスト向け。2026/9/22 GA。音声 $0.009/分（2027/1/1 以降 $0.018/分）。無料枠あり。公式の課金単位はトークン（Input $0.50 / 1M tok、Audio Output $6.00 / 1M tok。2027/1/1 以降は $1.00 / $12.00）。
- **Gemini 3.8 Flash TTS**（キー `gemini-3-flash-tts` / API モデル `gemini-3.8-flash-tts`）: 表現力・音質重視のフラグシップ。2026/9/22 GA。音声 $0.0135/分（2027/1/1 以降 $0.027/分）。無料枠あり。公式の課金単位はトークン（Input $0.50 / 1M tok、Audio Output $9.00 / 1M tok。2027/1/1 以降は $1.00 / $18.00）。
- 声のデザイン・複製・リミックス（Voices API）は未対応。
- 無料枠の RPM / TPM / RPD は Google が公開固定値を廃止し、プロジェクト単位で AI Studio の Rate Limits ダッシュボードに表示される方式に変更されている。本アプリでは無料枠キー使用時に「無料枠あり・実際の上限は AI Studio のレート制限ページで確認」という注釈（`gemini.model.freeTier.tts`）のみを表示し、固定の参考値は提示しない。
- TTSモデル選択時、ParameterPanelに以下を追加表示する:
  1. **スタイル**: 9種のプリセット + `カスタム`の選択肢を持つドロップダウン（表示形式 "スタイル名 : 効果"）。プリセット選択で下段のスタイル内容欄に該当する英語プロンプトが自動展開される。
  2. **スタイル内容**: 複数行テキスト入力。手動で編集するとスタイル選択は自動的に`カスタム`になる。
  3. **ボイス**: 30種の事前定義ボイスを "ボイス名 : 特徴" 形式で選択。
- プロンプト欄のラベルは「話させたい内容」に差し替わる。参照画像UIは非表示。
- Audio Tags 対応モデル（`gemini.supportsAudioTags`）では、プロンプト欄ラベル右に「Audio Tags の使い方」ボタンを表示。クリックで解説ダイアログを開く。ダイアログは Gemini 3.8 系の指示の分かれ方に合わせた2区分（「原稿内に書くタグ（発声・間）」と「スタイル欄で指定するもの（話速・トーン）」）で構成する。
- APIリクエスト:
  - エンドポイント: `/v1beta/interactions`
  - 入力は `[{type:'user_input', content:[{type:'text', text:<ユーザー入力>, annotations:[{type:'speech_metadata', style:<英語スタイル指示>}]}]}]`。3.8 系は本文を逐語トランスクリプトとして扱うため、スタイル指示は本文に混ぜず `speech_metadata` に載せる（スタイルが空なら `annotations` を省略）。
  - `generation_config.speech_config: [{voice: <ボイス名>}]`
  - `response_format: {type:'audio', mime_type:'audio/l16', sample_rate:24000}`。3.8 系の単発リクエストの既定出力は WAV だが、既存の PCM→MP3 変換をそのまま通すため raw PCM を明示要求する。
  - 応答は `output_audio` から取得し、interaction ID とトークン使用量を履歴に記録する。
- APIは raw PCM（例: `audio/L16;codec=pcm;rate=24000`）で返却される。後処理は次の順で行う:
  1. メモリ上で同梱ffmpegを介して MP3 に変換（CBR 160 kbps, 48 kHz, mono）。成功時は `.mp3` で保存。
  2. ffmpegが利用不可・失敗した場合は、純JSで RIFF/WAV ヘッダ（44バイト）を付与した WAV を `.wav` で保存。これによりAPIが成功している（=トークンが消費されている）にもかかわらず後処理失敗で結果が破棄されることを防ぐ。
- `HistoryEntry.styleInstruction` / `voice` にも保存され、履歴からの復元で元のスタイル/ボイスに戻る。
- 1リクエストあたりのテキスト長の上限は、現行の Gemini 3.8 系 TTS では公開されていない（旧 2.5 系では 4,000 バイトと明記されていた）。アプリ側でも文字数制限は設けていないため、長文は API のエラーで初めて判明する。

### 3.5 画像ビューア

- モードレスウィンドウとして開く（複数同時に開くことが可能）。
- 初期サイズは画像の等倍ピクセルサイズ。画面サイズの90%を超える場合は縮小して表示する。
- ウィンドウリサイズ時に画像は縦横比を維持して拡大・縮小する。

### 3.6 動画ビューア

- モードレスウィンドウとして開く。HTML5 `<video>` 要素による再生コントロール（再生/一時停止、シーク、音量）付き。
- 自動再生で開始される。

### 3.7 設定

- **言語**: i18nextによる日本語/英語切り替え。変更は即時反映。翻訳データは`src/renderer/i18n/locales/`に一元管理される。
- **テーマ**: ライト/ダーク/システム（OS追従）。変更は即時反映。
- **APIキー**: Electronの`safeStorage`で暗号化保存。マスク表示と表示/非表示トグル付き。以下の3種類のキーを最大7つ（デフォルト1・無料枠1・カスタム最大5）まで保持可能。
  - **デフォルトキー**: タイトルなし。通常利用想定。
  - **無料枠キー**: タイトルなし。このキーを選択中はモデルの料金ではなく無料利用枠の情報が表示される。
  - **カスタムキー**: タイトル付きで最大5つ追加可能。各キーに「無料枠キーとして扱う」フラグを設定できる。
  - キャプションバー（タイトルバー）の切替UIで、現在有効なキーを切り替える。アクティブキーが生成APIリクエストに使用される。
  - アクティブキーが無料枠種別の場合、ParameterPanelではモデル毎の参考価格は非表示となり、代わりに無料利用枠の情報（利用可否等）が表示される。両者は相反関係で同時表示されない。
- **履歴保存先**: ユーザーが任意のディレクトリを選択可能。変更時に既存履歴の移動有無を確認するダイアログを表示。

### 3.8 配布アーティファクト後処理 (Windows portable の zip 化)

- `electron-builder.yml` の `afterAllArtifactBuild` フックに `scripts/zip-portable.js` を指定し、Windows portable `.exe` をビルド完了後に `.zip` 圧縮する。未署名 `.exe` を直接配布するとブラウザやウイルス対策ソフトの警告が厳しいため、portable 版は zip 形式で配布する。
- フック内の処理:
  1. `context.platformToTargets` を走査し、Windows プラットフォーム上に `portable` ターゲットが含まれる場合のみ処理を行う (macOS / Linux ビルドでは何もせず通過する)。
  2. `context.artifactPaths` から `.exe` を抽出し、同 basename の `.exe.blockmap` が `artifactPaths` に含まれない `.exe` のみを portable 版として扱う。NSIS は `.exe` と `.exe.blockmap` を必ずペアで出力するため、`.blockmap` を伴わない `.exe` は確実に portable 版である。
  3. `archiver` (zlib level 9) で同名 `.zip` を生成し、成功後に元 `.exe` を削除する。
  4. 生成した zip パスの配列を戻り値として返す。electron-builder はこれを publish 対象アーティファクトに追加するため、`yarn release:win` 実行時には GitHub draft release に zip が含まれる。
- NSIS 関連アーティファクト (`.exe`, `.blockmap`, `latest.yml` など) は変更・削除しない。

## 4. データフロー

### 4.1 生成フロー

1. Renderer: ユーザーがパラメータを設定し、生成ボタンをクリック
2. Renderer -> Main (IPC): `generation:execute`でGenerationParamsを送信
3. Main: 履歴件数が上限を超えていないか検証
4. Main: API呼び出し
   - 画像: Interactions API `interactions.create`（生成枚数分ループ）
   - 動画: Interactions API `interactions.create`（同期）→ inline Base64 または URI ダウンロード
   - 音楽: Interactions API `interactions.create` → `output_audio` / `output_text`
   - 音声 (TTS): Interactions API `interactions.create` → `output_audio`（raw PCM）→ MP3 再エンコード
5. Main: 生成ファイルとメタデータを履歴ディレクトリに保存
6. Main: サムネイルを生成（画像: Electron nativeImage。透過を含みうる画像（WebP、透過チャンネル付き PNG）は ffmpeg で市松模様に重ねて変換。動画: ffmpeg、音楽: サムネイルなし）
7. Main -> Renderer (IPC): HistoryEntryを返却
8. Renderer: 履歴一覧を再読み込み

### 4.2 API通信

- **Gemini クライアントの API バージョン**: `@google/genai` は既定で `v1` を使うが、Interactions API は `v1beta` で提供され、プレビュー版モデルの一部も `v1beta` にしか無い。そのため `new GoogleGenAI({ apiKey, apiVersion: GEMINI_API_VERSION })`（`'v1beta'`）で明示する。API キーの接続テストも同じバージョンで行う。
- **API に送るモデル ID**: リクエストの `model` にはモデル定義のキー（`id`）ではなく `resolveApiModelId()` で解決した `apiModelId` を送る（6.0 参照）。
- **Nano Bananaモデル**: Interactions API（`/v1beta/interactions`、SDK の `ai.interactions.create`）を使用。入力はコンテンツブロック配列（`{type: 'text', text}` のプロンプト + `{type: 'image', data, mime_type}` の参照画像）で、出力形式は `response_format: {type: 'image', aspect_ratio, image_size}` で指定する（`image_size` は `1K` / `2K` / `4K`。大文字の K が必須）。`response_format` に画像を指定することで会話テキストの返却も抑制される。ネガティブプロンプトはテキストプロンプト内に埋め込み。1リクエストにつき1枚（`output_image`）なので、生成枚数分ループする。ループ内の1リクエストが失敗しても残りは継続し、全滅した場合のみ診断情報をまとめてエラーにする。
- **URI 配信**: Interactions API 経路（全メディア）では、レスポンスが inline Base64（`data`）ではなく URI（`uri`）で返された場合、`x-goog-api-key` ヘッダー認証でダウンロードしてメモリ上の Buffer にする（4K 画像や長尺の動画・音声は inline 上限を超えうる）。生成結果はすべて Buffer として履歴サービスに渡し、履歴サービスが最終保存先へ書き込む。
- **Gemini Omni Flashモデル**: Interactions API を使用。入力はコンテンツブロック配列（参照画像ブロック + プロンプト）、出力形式は `response_format: {type: 'video', aspect_ratio: '16:9' | '9:16', resolution: '360p' | '720p' | '1080p' | '4k', duration: '3s'〜'15s'}` で指定する。リクエストは同期型で、レスポンスの `output_video` から動画（Base64 または URI）を取得する。`status !== 'completed'` または動画欠落時は `NO_VIDEO_GENERATED` エラーとして `status` / `output_text` を診断情報に載せる。
- **Lyriaモデル**: Interactions API を使用。入力は参照画像ブロック + プロンプトのコンテンツブロック配列で、`response_format` は指定しない（既定の MP3 出力を使う）。音声は `output_audio` から取得する。テキストは `output_text` を使わず、`steps` の全 `model_output` ステップを走査して `text` ブロックを 1 ブロック = 1 要素で収集する（`collectInteractionTexts()`）。`output_text` は SDK 仕様で「最後の model_output の連結テキスト」であり、歌詞と楽曲構成 JSON のように複数ブロックがある場合に境界が失われ、前段ステップのテキストも脱落するため使えない。
- **Gemini 3.8 TTSモデル**: Interactions API を使用。入力は `user_input` ブロックで、スタイル指示は `speech_metadata` アノテーションに載せる。ボイスは `generation_config.speech_config`、出力形式は `response_format: {type:'audio', mime_type:'audio/l16', sample_rate:24000}` で指定し、`output_audio` の raw PCM を MP3 に再エンコードする。テキストは Lyria と同じく `collectInteractionTexts()` で全ブロックを収集する（TTS は音声のみの出力と公式に記載されているが、返った場合は破棄しない）。
- **SDK の型で検証する方針**: Interactions API の `response_format` は SDK のユニオン型に `{ [k: string]: any }` のキャッチオールが含まれるため、フィールド名を綴り間違えてもコンパイルが通り、API 側で黙って無視される。これを防ぐため、`gemini-service.ts` にローカルの狭い型（`ImageResponseFormat` / `AudioResponseFormat` / `VideoResponseFormat` / `InteractionContentBlock`）を定義し、リクエストオブジェクトはそちらで注釈する。レスポンス型は SDK の戻り値型から導出する（ストリーミング分岐は `status` フィールドで除外）。
- **診断情報**: Gemini の全生成経路は Interactions API で、失敗情報は `status` と `output_text` のみ。候補単位の安全性内訳（generateContent の `finishReason` / `safetyRatings` / `promptFeedback`）は取得できない（履歴 JSON の当該フィールドは過去エントリの互換用として型に残している）。
- 参照画像はリクエスト時にローカルファイルパスからBase64エンコードして送信
- APIキーはリクエスト時に暗号化ストレージから取得

## 5. セキュリティ

- APIキーはElectronの`safeStorage`の非同期 API（`isAsyncEncryptionAvailable` / `encryptStringAsync` / `decryptStringAsync`）により暗号化して保存される。復号時に `shouldReEncrypt` が返された場合（OS 側の鍵の更新など）は、その場で再暗号化して保存し直す。
- RendererプロセスはAPIキーに直接アクセスせず、すべてのAPI操作はMainプロセス経由のIPC通信で処理される。
- コンテキスト分離とPreloadスクリプトにより、WebコンテンツとNode.js APIの間に安全な境界を確保する。

## 6. 拡張性

- モデル定義は`shared/constants.ts`に一元管理されている。新モデル追加時はこのファイルのみを更新する。
- 各モデル定義には対応パラメータが含まれ、UIの有効/無効制御が自動的に行われる。生成バックエンドのディスパッチは`mediaType`で行い、Gemini の全メディアは Interactions API 経路で処理される。
- モデル定義のAPIプロバイダフィールドにより、将来的な複数プロバイダ対応に備えている。
- APIキーストレージはプロバイダ別にキー管理されており、複数APIキーに対応可能。

### 6.0 モデルキーと API モデル ID

- モデル定義の `id` はアプリ内のモデルキーで、**モデル系統のメジャーバージョン単位で固定**する（例: `gemini-nano-banana-2`、`gemini-omni-1-flash`、`lyria-3`、`gemini-3-flash-tts`、`gpt-image-2-flare`）。履歴エントリの `model`、履歴フィルター、パラメータ復元はこのキーで動く。
- API へ送るモデル ID は `apiModelId` に持ち、表示名 `displayName` は実際に使うバージョンの名前にする（例: キー `gemini-nano-banana-2` → API `gemini-nano-banana-2.1`、表示名「Nano Banana 2.1」）。マイナーバージョンが上がった場合は、同じエントリの `apiModelId`・`displayName`・対応パラメータ・料金だけを更新し、キーは変えない。
- メジャーバージョンが変わった場合は新しいキーのエントリを追加し、旧キーは 6.1 の手順で廃止モデルへ移す。
- `resolveApiModelId()` がキーから `apiModelId` を解決する（未宣言ならキーをそのまま返す）。モデルセレクタ直下の等幅表示もこの値（実際に使うモデル ID）を表示する。
- 履歴エントリには生成時の `apiModelId` も記録し、どのバージョンで生成したかを後から追えるようにする。

### 6.1 廃止モデルの扱い

提供元がシャットダウンしたモデル、系統が終わったモデル、別系統のモデルに置き換わったモデルは、生成用の `MODEL_DEFINITIONS` から取り除き、`RETIRED_MODEL_DEFINITIONS` へ移動する。これにより新規生成では一切選択・実行できなくなる（生成モデル選択UI・プロバイダディスパッチは `MODEL_DEFINITIONS` のみを参照する）。一方で、過去にそのモデルで生成した履歴は引き続き完全に利用可能とする:

- 履歴フィルターのモデル一覧は `ALL_MODEL_DEFINITIONS`（= `MODEL_DEFINITIONS` + `RETIRED_MODEL_DEFINITIONS`）をマージし、実際に履歴に存在するモデルIDに絞り込んで構築する。廃止モデルの履歴が存在する場合のみフィルター候補に現れる。
- 履歴エントリのモデル名表示は保存済みの `modelDisplayName` を用いるため、定義の有無に依存しない。
- 廃止モデルの履歴からパラメータを復元する際は、`RETIRED_MODEL_DEFINITIONS[].replacementModelId`（移行先モデルID）に置換したうえで、移行先モデルの対応パラメータ（アスペクト比・解像度・品質・動画の長さ・動画解像度・枚数・参照画像数など）にクランプする。動画の長さは移行先が対応する長さのうち最も近い値に寄せる。これによりプロンプト・フィルター等は引き継ぎつつ、モデルとしては必ず移行先が選択される。移行先自体が後に廃止された場合も `resolveRestoreModelId()` が置換を再帰的にたどるため、必ず選択可能なモデルに着地する（ホップ数は定義数で上限を設け、循環参照でも停止する）。
- 「シャットダウン日が未発表でも、提供元が上位互換モデルを出して旧モデルを実質的に新規利用不可としたもの」も廃止モデルとして扱う。判断根拠はモデル定義のコメントに残す。
- バージョン入りのキーを使っていたモデル（下表「キー体系の変更」）も廃止モデルとして扱い、同じ系統のメジャーバージョン単位のキーへ移行する。旧キーで生成した履歴は、フィルター上は旧キーの項目として表示する（別名による統合はしない）。新キーと表示名が同じになる場合は、フィルターで同名の項目が並ばないよう、表示名に旧キーを括弧で添える。
- 現在の廃止モデルは 8.1 の表を参照。

- Nano Banana 系の正式な課金単位は image tokens + text tokens の組合せ（Nano Banana 2.1 は画像出力 $30 / 1M tok、Nano Banana Pro は $120 / 1M tok）だが、UI上は分かりやすさを優先して公式ページの1枚あたり料金を表示する。
- Gemini Omni 1.2 Flash の正式な課金単位は出力動画トークン（$12.00 / 1M tok）。解像度ごとの1秒あたりトークン数（360p 1,931 / 720p 5,792 / 1080p 8,688 / 4K 17,376）を掛けた公式ページの換算値を表示する。720p は公式ページが「約 $0.07」としているため `~` を付ける。
- Preview ステータスのモデルは料金が予告なく変更される可能性がある。
- **参考コストはトークン単位で表示しない**。トークン数は利用者が見積もれないため、`costLabel` には利用者が判断できる単位（1枚あたり / 1秒あたり / 1分あたり / 1曲あたり）に換算した値のみを載せる。公式の課金単位と換算式はこのドキュメントとモデル定義のコメントに記録する。
- TTS の分単価は、提供元が示す換算係数「音声1秒 = 25 トークン」（= 1分 1,500 トークン）を用いて算出している。Audio Output $6.00 / 1M tok → $0.009/分、$9.00 / 1M tok → $0.0135/分。テキスト入力（$0.50 / 1M text tok）は、1分の読み上げ原稿を多めに 500 トークンと見ても $0.00025/分にとどまり四捨五入すると消える額なので、`costLabel` には載せない。
- Gemini 3.8 系 TTS の料金は 2026/12/31 までの導入価格で、2027/1/1 に倍額となることが公表されている。`costLabel` の 2 行目に `2027/1/1~ $0.018/min` のように「適用開始日 + 単価」で記載する。説明文を足したり、モデル専用の翻訳キーを新設したりはしない。なお `costLabel` は i18n を経由しない共有定数なので、値は言語非依存（英数字と記号のみ）で記述する。提供元自身が概算としている値にだけ `~` を前置し、それ以外の行には概算記号を付けない。
- GPT Image 2.6（Flare / Sunburst）は OpenAI が新規実装に推奨する現行世代であり、本アプリの OpenAI 側はこの2モデルのみを提供する。`xhigh` / `max` の品質段階と透過背景（PNG / WebP）に対応する。Flare と Sunburst は用途（Flare = 日常の高速生成、Sunburst = 編集精度重視）だけが異なり、トークン単価は同じ。2.6 で追加された complexity 設定に対応する（3.1.1 参照）。アニメーション GIF 出力・SVG 出力は扱わない。
- **1枚単価の算出方法**: OpenAI は 2.5 / 2.6 系について静的な価格表を公開しておらず、ドキュメント上は対話型の料金計算ツール（画像生成ガイド内の `GptImageTokenCalculator`）のみである。本アプリは、その計算ツールのソースに含まれる式と係数を `shared/openai-cost.ts` にそのまま実装し、`costLabel` もこの関数で生成する（`buildOpenAICostLabel()`）。長辺の係数（Low 16 / Med 24 / High 48 / XHigh 64 / Max 96。gpt-image-2 は Low 16 / Med 48 / High 96）を長辺側のパッチ数、それを縦横比で割った値（0.5 ちょうどは偶数丸め）を短辺側のパッチ数とし、`ceil(パッチ数の積 × (2,000,000 + 画素数) ÷ 4,000,000)` トークンを求める。GPT Image 2.6 はさらに品質段階ごとの倍率（Low 4.2 / Medium 3.3 / High・XHigh・Max 1）を掛けて四捨五入する。これに画像出力単価 $30 / 1M tok を掛けた値を小数第3位に丸めて表示する。この式は公式ドキュメントに価格表がある gpt-image-2 の3サイズの掲載値を完全に再現する。トークン単価（画像入力 $8 / 出力 $30 / 1M tok、テキスト入力 $5 / 1M tok）は 2.5 と 2.6 で同一であることを公式料金表で確認している。
- 料金は画素数に比例しない（式の `(2M + 画素数) / 4M` の項により逓減する）。そのため **横長4K（3840x2160）は2Kスクエア（2048x2048）より安い**。公式ドキュメントにも同旨の注記がある。
